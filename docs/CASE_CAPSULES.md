# MK11 · Portable Case Capsules

**Pattern Atlas v1.1.0 · November 6, 2026**

## Why capsules exist

The research tools in MK8–MK10 provide a structured case audit, local PDF fingerprints, and optional event-linked handling histories. MK11 lets a researcher package those layers together with explicit privacy controls, validate the package on another computer, and compare its case snapshot to the currently opened Atlas case.

A capsule is an **offline research snapshot**, not a database synchronization protocol, judicial evidence certificate, provenance attestation, or proof that a source's claims are true.

## Three layers

**Layer 1 · Selected case and curated audit (always included)**

The complete selected case file, its existing source-to-claim/hypothesis audit, open evidentiary gaps, and curated transaction-candidate metadata. A case created or edited locally might contain **private researcher-authored content**. Review it before sharing, even with both optional switches off.

**Layer 2 · Original-document fingerprint manifest (off by default)**

If explicitly enabled, includes researcher-entered original PDF metadata, filenames, download URLs, local SHA-256 hashes, page-specific observations, and written research notes. It does **not** include PDF bytes, rendering, or the PDF's extracted text. Personal or otherwise sensitive information may exist inside the notes or filenames.

**Layer 3 · Evidence handling journal (off by default)**

If explicitly enabled, contains researcher labels, self-reported actions, recorded dates, written notes, individual handling-event hashes, and the current journal head. This layer requires the exact original-document manifest from Layer 2. MK11 checks every referenced document/source and replays the original handling event hashes before including it.

The capsule format includes a privacy declaration which must exactly match the layers present. An import containing undeclared extra fields is rejected.

## Export procedure

1. Select the case in Pattern Atlas.
2. Open **Case capsule** in the sidebar.
3. Review the always-included **selected case**. Do not assume a local case is free of private details.
4. Optionally enable **Include private PDF fingerprint manifest**. If MK9's saved manifest is stale, the optional layer remains locked until the user independently recovers that storage.
5. Optionally enable **Include private handling journal**, which requires a complete, validated MK9 manifest. MK10's hash sequence is validated.
6. Select **Export selected case capsule + SHA-256**.

Nothing is transmitted to a remote server by this feature. JSON downloads are generated by the browser. The capsule has a **3.5 MB payload limit**.

## Read-only verification procedure

Select another capsule JSON file using the **Verify without importing** panel.

The browser will:
- Parse its JSON, check size, format, allowed fields and explicit privacy flags.
- Recompute the outer SHA-256 digest over a canonicalized complete payload.
- Validate the enclosed case file and independently regenerate the source-to-claim audit.
- Validate the original PDF manifest if present, including source IDs, dates, saved URLs, file names, PDF byte sizes, SHA-256 values and mandatory page-note limitations.
- Revalidate the original handling chain if present, including all referenced PDF fingerprints, event ordering, event hashes and final head.
- Report case, source, claim, PDF-note and handling counts.
- Compare the capsule's case snapshot with the currently selected case and label **different case**, **same case with differences**, or **identical snapshot**.

**Verification never saves, imports, merges, or overwrites any local case, PDF manifest, or handling journal.** The file's contents are discarded after the check except for its non-sensitive result summary.

## Integrity is not authenticity

A SHA-256 digest detects changes to a packet **relative to its recorded digest**. A person who controls the entire packet can rewrite the case and regenerate the digest; an independently preserved signature or digest is necessary for stronger accountability. A correctly rehashed, self-consistent capsule may still be historically false.

Likewise, MK10 event hash links record a self-reported history. Their validation does not establish who handled a document, whether an electronic timestamp is externally trusted, bank settlement, software delivery, or anyone's culpability.

For stronger provenance in future rungs, consider optional public-key signing and independently retained signed manifests, with appropriately managed keys. Do not overstate what unsigned self-contained hashes demonstrate.

## Testing

Run `npm test` and `npm run build`.

MK11 adds regression tests for default privacy exclusions, each optional evidence layer, handling-to-document dependencies, source URL drift, modified page notes, forged/rehashed audit matrices, event hash corruption, incorrect privacy declarations, wrong-case capsules, case drift, malformed envelopes and size limits.

**Ledger Above Ego. Evidence Above Assumption.**

## MK12 optional researcher signatures

MK11 capsules remain **unsigned** and verifiable exactly as before. The new **Capsule signatures** sidebar page accepts an already exported MK11 capsule and produces a *separate signed wrapper*, keeping existing research data and privacy flags intact. The wrapper can be verified offline with its embedded public key; an independently trusted key fingerprint is required before attributing the signature to an expected signer. See [MK12 signing protocol](SIGNED_CAPSULES.md).
